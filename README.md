# Verde Market

[![CI](https://github.com/akoody/verde-market/actions/workflows/ci.yml/badge.svg)](https://github.com/akoody/verde-market/actions/workflows/ci.yml)

![Verde Market — фермерские продукты напрямую от хозяйств](docs/assets/cover.png)

Маркетплейс фермерских продуктов: каталог, корзина и оформление заказа сразу у нескольких продавцов. Покупатели отслеживают доставку, фермеры ведут товары и заказы, администратор проверяет магазины и публикации.

**Стек:** Next.js 16 (App Router), React 19, TypeScript, MongoDB + Mongoose, Zustand, Zod, Tailwind.

## Что умеет

- **Покупатель:** каталог с поиском и фильтрами, карточка товара, избранное, корзина, оформление заказа без регистрации, отслеживание заказа по токену, история заказов в аккаунте.
- **Продавец:** магазин и настройки доставки, товары с фотографиями, остатки, смена статусов заказов.
- **Администратор:** допуск магазинов и товаров к продаже.

## Как устроено

Модульный монолит: модули `auth`, `catalog`, `cart`, `stores`, `orders`, `moderation`, `media` отделены от HTTP-маршрутов и интерфейса. UI не импортирует серверные реализации, и ESLint это проверяет. Подробнее: [docs/architecture.md](docs/architecture.md).

Ключевые решения:

- **Checkout в транзакции MongoDB.** Один checkout создаёт отдельный заказ на каждый магазин. Остатки уменьшаются условным обновлением, поэтому параллельные заказы не продают больше, чем есть. Если что-то не прошло (например, минимальная сумма заказа), откатывается весь checkout.
- **Идемпотентность.** Уникальный индекс `(checkoutId, storeId)`. Повтор возвращает существующие заказы только с тем же токеном доступа и отпечатком содержимого; повтор с изменёнными данными отклоняется.
- **Снимок заказа.** Цены, названия и условия доставки копируются в заказ и не меняются вместе с каталогом.
- **Статусы заказа** задаёт один модуль; отмена возвращает остатки в той же транзакции и не выполняется дважды.
- **Публикация.** Каталог, карточка и sitemap показывают только активные товары проверенных магазинов; фильтр применяется до пагинации, поэтому счётчики сходятся.
- **Схема базы** меняется отдельной командой `db:migrate`, а не HTTP-запросами.

## Запуск

Нужны Node.js 22 и MongoDB **replica set** (Atlas или локальный replica set): на одиночном сервере транзакции не работают.

```bash
cp .env.example .env     # MONGODB_URI, AUTH_SECRET (openssl rand -hex 32), учётка для seed
npm ci
npm run db:migrate       # индексы
npm run seed             # стартовый каталог и аккаунт владельца
npm run dev
```

Продакшен: `Dockerfile` и `compose.production.yaml`, пример nginx в `deploy/nginx`. Загруженные изображения хранятся в `UPLOAD_DIR`.

## Проверки

```bash
npm run check    # ESLint, TypeScript, интеграционные тесты, Prettier
npm run build
```

Интеграционные тесты поднимают MongoDB replica set в памяти (`mongodb-memory-server`) и проверяют идемпотентность checkout, откат при ошибке, защиту от перепродажи при параллельных заказах, видимость непроверенных магазинов и правила регистрации. CI запускает всё это на каждом PR.

## Ограничения

- Оплата только при получении; онлайн-платежей нет.
- Гостевой заказ отслеживается по токену в браузере: на другом устройстве или после очистки данных его не найти без входа в аккаунт.
- Изображения лежат на диске одного экземпляра приложения; для нескольких экземпляров нужно объектное хранилище.
- `seed` обновляет ассортимент и пароль bootstrap-аккаунта, поэтому в продакшене его запускают только осознанно.
