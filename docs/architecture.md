# Архитектура

Приложение — модульный монолит. Разделение проходит по бизнес-сценариям; отдельные процессы и универсальные repository-обёртки пока не нужны.

## Модули

| Модуль     | Ответственность                                                          |
| ---------- | ------------------------------------------------------------------------ |
| auth       | Проверка учётных данных, создание пользователей, сессии, формы входа     |
| catalog    | Публичный ассортимент, преобразование документов в DTO, карточки и поиск |
| cart       | Локальная корзина и общий расчёт стоимости в минимальных единицах валюты |
| stores     | Создание магазина, настройки доставки, выборка кабинета продавца         |
| orders     | Валидация оформления, резерв остатков, статусы и гостевое отслеживание   |
| moderation | Допуск магазинов и товаров к продажам                                    |
| media      | Хранение изображений продавцов                                           |

Внутри модуля `schemas.ts`, типы и правила могут использоваться клиентом. `server/` содержит Mongoose-модели, сервисы записи и функции чтения. UI не импортирует серверные реализации. ESLint запрещает такие зависимости для компонентов, shared UI и клиентских stores/hooks.

Маршрут проверяет origin, сессию, роль и входные данные; сервис выполняет бизнес-операцию. Серверная страница получает read model из функции выборки и передаёт сериализуемые данные в UI. Межмодульные обращения явные: заказы используют каталог и магазины, модерация управляет публикацией обоих.

## Каталог

Источник цен, наличия и доставки — MongoDB. Публичные запросы выбирают только активные товары активных проверенных магазинов. Фильтрация магазинов выполняется до pagination и count, поэтому total соответствует доступному ассортименту. Fixtures импортирует только seed. Главная, подробная карточка и sitemap используют те же правила публикации.

## Заказы

Один checkout создаёт отдельный заказ на каждый магазин. В транзакции проверяются товары, количество, минимальная сумма и способ оплаты; остатки уменьшаются условным обновлением. При отказе весь checkout откатывается. Цены, названия и доставка сохраняются в заказе как снимок.

Уникальный индекс `(checkoutId, storeId)` защищает от повторной записи. Повторный запрос возвращает существующие заказы только с тем же токеном доступа и отпечатком содержимого. Старые заказы без отпечатка проверяются по токену. Переходы статусов задаёт один модуль, который используют сервис и кнопки продавца. Отмена и возврат остатков проходят в одной транзакции; повторная отмена недопустима.

## Эксплуатация

Индексы обновляются через отдельную команду; HTTP-запросы не меняют схему базы. Seed не сбрасывает остатки существующих товаров, но обновляет ассортимент и пароль bootstrap-аккаунта, поэтому его запускают только осознанно. Сбой подключения очищает rejected promise и позволяет следующему запросу подключиться заново.

Известные бизнес-ограничения перечислены в README. Локальные проверки подтверждают исходники и тестовую среду; выкладку, рабочую MongoDB и реальные заказы проверяют отдельно.
